# Базис

Веб-сервис для **автоматического учёта и оценки продуктовых решений команд**
на хакатонах. Принимает заявки команд (репозиторий, документация, презентация,
скринкаст), выполняет автоматические проверки артефактов, даёт жюри панель
экспертной оценки по настраиваемым критериям и формирует итоговый рейтинг.
Дополнительно — модуль проверки алгоритмических задач с песочницей.

---

## Возможности

- **Роли и доступ:** участник, жюри, организатор. Регистрация создаёт только
  участника; роли жюри назначает организатор (повышением по email или созданием
  аккаунта). Пароли хранятся в виде bcrypt-хэшей, авторизация — по JWT.
- **Команды и заявки:** создание команд, вступление по заявке с подтверждением
  капитана, исключение участников, удаление команды. Один участник — одна команда
  на хакатон.
- **Подача решения:** ссылки **или загрузка файлов** для репозитория (zip),
  документации (PDF/DOCX/MD), презентации (PPTX/PDF) и скринкаста
  (MP4/MOV/WEBM/MKV/AVI); обновление до дедлайна, загрузка только на идущий хакатон.
- **Автоматические проверки** (асинхронно через Celery):
  - **код** — README/лицензия/зависимости/инструкция запуска, LOC, цикломатическая
    сложность, поиск секретов, линтер (pylint для Python + ESLint для JS/TS);
  - **документация** — обязательные разделы, объём, изображения (PDF/DOCX/Markdown);
  - **презентация** — количество слайдов и структура по настраиваемым организатором
    разделам (PPTX/PDF);
  - **скринкаст** — наличие, длительность, разрешение, кодек и краткое текстовое
    описание для жюри (опционально — автоматическая транскрипция речи, если
    подключён движок распознавания).
- **Оценка жюри:** настраиваемые критерии и веса, оценки с комментариями,
  взвешенный итоговый балл (авто 40% + жюри 60%), публичный рейтинг команд.
- **Уведомления:** заявки в команду, решения по заявкам, изменения статуса.
- **Алгоритмический модуль:** задачи с тестами и лимитами, запуск решений в
  изолированной песочнице, вердикты OK/WA/TL/ML/RE/CE, история попыток.

## Стек

- **Frontend:** React + TypeScript, Vite, Tailwind CSS, React Router, Tabler Icons.
- **Backend:** FastAPI, SQLAlchemy 2 (async), Alembic, Celery.
- **Хранилище:** PostgreSQL, Redis (брокер очередей и кэш).
- **Инфраструктура:** Docker / Docker Compose.

## Всё одной командой (Docker)

В корне есть общий `docker-compose.yml`, поднимающий **весь проект** — БД, Redis,
API, воркер и фронтенд. Нужен запущенный Docker Desktop.

```bash
cp backend/.env.example backend/.env   # только в первый раз
docker compose up --build
docker compose up # после билда можно запускать так
```

После сборки откройте **<http://localhost:5173>** — фронтенд (nginx) сам проксирует
`/api` на бэкенд. Swagger по-прежнему на <http://localhost:8000/docs>.

Ниже — как поднимать части по отдельности (бэкенд в Docker + фронтенд в dev-режиме).

## Запуск бэкенда

Бэкенд полностью контейнеризирован — БД, Redis, API и воркер поднимаются одной
командой. Локально устанавливать Python, PostgreSQL и т.д. **не нужно**.

### 1. Предусловия

- **Docker Desktop** (Windows / macOS) или Docker Engine + Compose v2 (Linux).
  Скачать: <https://www.docker.com/products/docker-desktop/>.
  - На **Windows** при установке включите **WSL 2 backend** (Docker Desktop
    предложит сам; нужна включённая виртуализация в BIOS).
  - После установки **запустите Docker Desktop** и дождитесь статуса
    «Engine running» (зелёный кит в трее). Без запущенного Docker команды ниже
    выдадут `Cannot connect to the Docker daemon`.
- Проверьте, что Docker доступен из консоли:
  ```bash
  docker --version
  docker compose version
  ```

- **Свободные порты:** `8000` (API), `5432` (PostgreSQL), `6379` (Redis).
  Если что-то уже занято (например, локальный Postgres на 5432) — освободите порт
  или поменяйте маппинг в `backend/docker-compose.yml`.

### 2. Конфигурация окружения

Из корня проекта:

```bash
cd backend
cp .env.example .env       # Windows PowerShell: copy .env.example .env
```

### 3. Сборка и старт

```bash
docker compose up --build
```

Что произойдёт:

1. Соберётся образ (Python + Node + ffmpeg + зависимости). **Первая сборка
   идёт дольше** — скачиваются базовые образы и пакеты. Повторные сборки быстрые:
   загрузки кэшируются (BuildKit cache), а слой зависимостей не пересобирается,
   пока не менялись `requirements.txt` / `lint/package.json`.
2. Поднимутся PostgreSQL и Redis, дождутся готовности (healthcheck).
3. API применит **миграции** (`alembic upgrade head`) и засеет **демо-данные**
   (`scripts.seed`), затем стартует uvicorn.
4. Запустится Celery worker для авто-проверок.

Готово, когда в логах появится строка uvicorn `Application startup complete`.

### 4. Что доступно

| Сервис        | Адрес                          | Назначение                         |
|---------------|--------------------------------|------------------------------------|
| API           | <http://localhost:8000>        | REST API                           |
| Swagger UI    | <http://localhost:8000/docs>   | интерактивная документация API     |
| PostgreSQL    | `localhost:5432`               | БД (`hackauth` / `hackauth`)       |
| Redis         | `localhost:6379`               | брокер очередей и кэш              |
| Celery worker | —                              | очереди `default`, `checks`, `judge` |

### 5. Остановка и сброс

```bash
# остановить (Ctrl+C в том же окне) или из другого окна:
docker compose down

# полный сброс вместе с данными БД (volume pgdata) и загруженными файлами:
docker compose down -v
```

Данные БД сохраняются между перезапусками в Docker volume `pgdata`; загруженные
артефакты — в `backend/uploads/`. Сид идемпотентен: на уже заполненной БД он не
создаёт дубликаты.

### Мелочи, о которых стоит знать

- **Запускать `--build` нужно только** после изменения `Dockerfile`,
  `requirements.txt` или кода. Для обычного старта достаточно
  `docker compose up` — образ переиспользуется.
- **Транскрипция скринкастов** по умолчанию **выключена** (движок распознавания
  речи не входит в образ — это заметно ускоряет сборку). Видео-проверка всё равно
  работает: длительность, разрешение, кодек и текстовое описание. Чтобы включить
  расшифровку речи, поставьте `faster-whisper` (модель задаётся `WHISPER_MODEL`).
- **ESLint-тулчейн** для проверки JS/TS-решений ставится внутрь образа при сборке
  (`backend/lint`), отдельная установка не требуется.
- **BuildKit** в Docker Desktop включён по умолчанию. Если сборка ругается на
  `RUN --mount`, запустите с `DOCKER_BUILDKIT=1 docker compose build`.
- Все команды `docker compose ...` выполняются **из папки `backend/`** (там лежит
  `docker-compose.yml`).

## Запуск фронтенда (dev)

Нужен **Node.js 18+** и npm.

```bash
cd frontend
npm install
npm run dev          # http://localhost:5173
```

Vite проксирует запросы `/api` на `http://localhost:8000`, поэтому при запущенном
бэкенде дополнительная настройка не нужна. Чтобы указать другой адрес API,
задайте `VITE_API_BASE_URL`. Прод-сборка: `npm run build`.

## Полезные команды

Выполнять из папки `backend/`:

```bash
# логи конкретного сервиса
docker compose logs -f api
docker compose logs -f worker

# smoke-тест API (внутри контейнера)
docker compose exec api python -m scripts.smoke

# повторный сидинг демо-данных
docker compose exec api python -m scripts.seed

# применить миграции вручную
docker compose exec api alembic upgrade head

# подключиться к БД
docker compose exec db psql -U hackauth -d hackauth
```

## Переменные окружения

Задаются в `backend/.env` (шаблон — `backend/.env.example`):

| Переменная               | По умолчанию              | Назначение                                  |
|--------------------------|---------------------------|---------------------------------------------|
| `SECRET_KEY`             | `change-me-in-prod-please`| ключ подписи JWT — **сменить в проде**      |
| `JWT_EXPIRE_MINUTES`     | `1440`                    | срок жизни токена (минуты)                   |
| `CORS_ORIGINS`           | `http://localhost:5173,…` | разрешённые источники (через запятую)        |
| `POSTGRES_*`             | `hackauth`                | хост/порт/пользователь/пароль/имя БД         |
| `REDIS_*`                | `redis` / `6379`          | подключение к Redis                          |
| `CELERY_BROKER_URL`      | `redis://redis:6379/1`    | брокер задач Celery                          |
| `CELERY_RESULT_BACKEND`  | `redis://redis:6379/2`    | бэкенд результатов Celery                     |
| `UPLOAD_DIR`             | `/app/uploads`            | каталог загруженных артефактов                |
| `MAX_UPLOAD_MB`          | `64`                      | лимит размера загружаемого файла              |
| `WHISPER_MODEL`          | `tiny`                    | модель транскрипции (если установлен faster-whisper) |
| `JUDGE_TIME_LIMIT_SEC`   | `2`                       | лимит времени на тест в алгоритм-песочнице     |
| `JUDGE_MEMORY_LIMIT_MB`  | `128`                     | лимит памяти на тест в алгоритм-песочнице       |

## Troubleshooting

- **`Cannot connect to the Docker daemon`** — не запущен Docker Desktop. Откройте
  его и дождитесь «Engine running».
- **`port is already allocated` / `address already in use`** — порт `8000`, `5432`
  или `6379` занят другим процессом. Освободите его или измените маппинг портов в
  `docker-compose.yml`.
- **API не стартует, ошибки подключения к БД** — Postgres ещё поднимается.
  Compose ждёт healthcheck, но при холодном старте дайте сервисам минуту;
  при необходимости перезапустите `docker compose up`.
- **Изменили зависимости, а они «не подхватились»** — пересоберите образ:
  `docker compose up --build`.
- **Начать с чистого листа** — `docker compose down -v` удалит БД и volume, после
  чего `docker compose up --build` поднимет всё заново с демо-данными.
